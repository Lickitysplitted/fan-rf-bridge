# Fan RF Bridge

Control RF-remote ceiling fans from Home Assistant, with two-way tracking: the
bridge transmits fan commands and also listens to the handheld remotes, so HA
stays in sync when someone uses the remote.

Hardware: a [wESP32](https://wesp32.com/) (PoE ESP32) running ESPHome, plus a
custom HAT carrying 433 MHz and 315 MHz ASK transmitters (NiceRF STX882) and
receivers (NiceRF SRX882S).

Supported fans (one transmitter per band drives every fan of that model; each
remote has its own ID):

| Model | Remote FCC ID | Band | Encoding | HA entities |
|---|---|---|---|---|
| A | 2ABUP-FT0317A | 433.92 MHz | 40-bit PWM: 24-bit remote ID + cmd byte ×2 | 6-speed fan + reverse button |
| B (Harbor Breeze) | A25-FA0188A | 315 MHz | Manchester OOK, replayed raw | 3-speed fan + light |

## Repo layout

| Path | What |
|---|---|
| `fan-control.yaml` | ESPHome config: TX scripts, RX decoders, fan/light entities |
| `fanb_codes.h` | Fan B raw pulse tables (TX) and the RX matcher |
| `secrets.example.yaml` | Template for `secrets.yaml` |
| `fanA-433.txt`, `fanA2-433.txt`, `fanB*-315.txt` | rtl_433 captures the codes were decoded from |
| `fanB_timings.json` | Fan B pulse trains extracted from the captures |
| `make_fana_iq.py`, `make_fanb_iq.py` | Generate HackRF IQ files to replay a command (used to verify codes before the hardware existed) |
| `fan A/B button presses.txt` | Order of button presses in the captures |
| `pcb/` | KiCad 10 project for the HAT, generated by `pcb/make_board.py`; Gerbers in `pcb/fan-hat-gerbers.zip`. See `pcb/README.md` |
| `case/` | 3D-printable case (tall base + magnetic lid). See `case/README.md` |

## Using it with your own fans

The remote IDs in `fan-control.yaml` and `fanb_codes.h` are for **my** remotes.
To use your own:

1. Capture each remote with an RTL-SDR and
   [rtl_433](https://github.com/merbanan/rtl_433) (`rtl_433 -f 433.92M -A` /
   `-f 315M -A`; 315 MHz needed low gain, `-g 9.9`).
2. Fan A: the 24-bit remote ID is the first 3 bytes of each frame; replace the
   `prefix:` strings and the `rid ==` checks in the RX lambda.
3. Fan B: replace the pulse tables in `fanb_codes.h` (decoded from the
   triq.org links rtl_433 prints).

Other remotes need their own decode, but the TX script / RX lambda / echo
suppression pattern carries over.

## Building the firmware

```sh
pip install esphome
cp secrets.example.yaml secrets.yaml        # then fill in a key
esphome run fan-control.yaml                # first flash over USB/serial
esphome run fan-control.yaml --device <ip>  # later updates over the network
```

The wESP32's V+ defaults to 12 V; **bridge its 5 V jumper** before fitting the
radios.

## Notes

- RF is one-way per command; fan state in HA is assumed, corrected by RX when a
  remote is used. Fan A power is a toggle code; Fan B light is a toggle.
- The bridge hears its own transmissions, so RX is ignored for 2 s after TX.
- Datasheets: wESP32 product brief (silicognition.com), NiceRF STX882 / SRX882
  (nicerf.com).
